General Requirements
* Output must be valid JSON.

1. Short answer (type: "short_answer")
* ONLY use this type for questions with a specific, factual answer that can be fully exhausted in the "answers" list (e.g., chemical symbols, specific terms). See the "carbon dioxide" or "Au" examples above.
* DO NOT use this type for open-ended questions with many possible correct answers (e.g., "Give an example of a non-living thing..."). If there are too many possibilities to list, do not use "short_answer".
* The learner types a free-form answer (no "o" multiple-choice list).
* "answers" must list every acceptable answer. Use more than one string when synonyms or alternative spellings are valid (e.g. ["int", "integer"]).
* In rare cases "answers" may be a single JSON string instead of an array; the app accepts both forms.
* "isCaseSensitive": use true if the user's typing must match capitalization exactly; use false or omit for case-insensitive checking (if omitted, treat as false).

2. Fill-in-the-Blank (type: "fill_blank")
* Count the number of "______" blanks in the question.
* The "answers" list must contain exactly the same number of items.
* "answers": list of correct answers in the exact order of the blanks (first blank → index 0, second → index 1, etc.).
* If the question has one blank, "answers" must contain exactly one item. If two blanks, "answers" will have two options.
* Include "other_options" with 3-4 alternative answers for validation purposes.

3. Match (type: "match")
* "left" and "right" must be lists with the same number of items (4-6 items recommended).
* The correct matches must be aligned by index.
* Keep all items short and clear.

4. True/False (type: "true_false")
* "correct" must be either "True" or "False".
* Statements must be clear and unambiguous.

5. Slider (type: "slider")
* "min": The minimum numerical value of the slider (must be integer).
* "max": The maximum numerical value of the slider (must be integer).
* "correct": The exact correct numeric answer. Ensure "correct" is between "min" and "max" inclusive.

6. Memory Grid (type: "memory")
* "pairs": A JSON object containing 3 to 6 key-value string pairs that the user must match.
* The keys should be short (e.g. terms), and the values should be their matching definitions.
* Ensure keys and values are unique and unambiguous.

7. Odd One Out (type: "odd_one_out")
* "options": A list of exactly 4 to 9 string items where all but one share a common characteristic.
* "correct": The single string item from "options" that does NOT belong. Must exactly match one of the items in "options".

8. Swipe Cards (type: "swipe_cards")
* "left_label": Text for the left swipe bin (e.g. "False" or "Immutable").
* "right_label": Text for the right swipe bin (e.g. "True" or "Mutable").
* "cards": A JSON object containing exactly 3 to 6 key-value string pairs. The keys are the card texts. The values must strictly be "left" or "right" depending on their category.

9. Word Scramble (type: "word_scramble")
* "answer": The correct one-word answer in all caps.
* "decoys": 2 to 4 decoy random uppercase letters to scramble alongside the answer (e.g. "ZQX").

10. Inline Dropdown (type: "inline_dropdown")
* "text": A sentence or short paragraph containing brackets with indices like `[0]`, `[1]`, etc. representing blanks.
* "dropdowns": An array of objects. Each object corresponds to the index in the text.
* Each dropdown object must have "correct" (the right string answer) and "options" (a list of 3 strings including the correct one).
